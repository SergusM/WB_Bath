# Веб-интерфейс (`html/index.html`) и Node-RED (`flows.json`)

## 1. Транспорт

- Интерфейс открывает WebSocket `ws://10.201.103.71:1880/control/`. В потоке ему соответствует узел `websocket in` с путём `/control/`.
- Любое сообщение интерфейса — это JSON. Он обрабатывается в потоке двумя параллельными ветками:
  1. `Usersetpoints` разбирает поля `{topic, value}`, то есть пользовательские уставки.
  2. `json` → `function 1` (берёт `msg = msg.payload`) → дальше сообщение уходит:
     - в `Main control`;
     - в switch `waterfall / light / RGBlight` → `function 2` → `Buttons`;
     - в `link out 10` → `Buttons` (сюда проходят все топики, кроме `Input 6`);
     - в switch `shedule*` → `Shedule waterfall`.
- Обратно `Main control` отдаёт объект `main` (через `rbe` → `json` → `websocket out`). В нём есть поля `tempsensors`, `setpoints`, `usersetpoints`, `heaters`, `buttons`, `Shedule`, `TP`, `TP_SPA`, `TP_SR`, `errormsg`, `timecatch`, `power_consumption`.

## 3. Где логика интерфейса и потока расходится

### 3.1. Ручной режим: изменённые уставки не применяются сразу
Значение из поля попадает только в `main.usersetpoints`. Копирование в `setpoints` в `Main control` закомментировано (строки 65–66). Новая уставка вступает в силу лишь после повторного нажатия «Ручной режим». При этом интерфейс сразу показывает новое значение в placeholder, и создаётся впечатление, что оно уже применено.

### 3.2. Ручной режим: «Выкл парение» гасит обе зоны только на экране
Когда `main.TP == "user"` и приходит `off`, сервер ставит `TP = TP_SPA = TP_SR = "off"`. Интерфейс показывает выключенными обе зоны. Но уставки обнуляются только у той зоны, где нажали кнопку (`PL` 0 или 1). **Вторая зона продолжает греться** с пользовательскими уставками, а в интерфейсе выглядит выключенной.

### 3.3. Часть зон в ручном режиме никогда не греется
- **Лежаки СПА-зоны** (`usersetpoints1`): цикл `i < 5` заполняет только `[0..4]`. Лежак 6 (`[5]`) остаётся с уставкой 0.
- **Потолок СПА-зоны** (`usersetpoints5`): заполняется только `[10]`, а `[11]` остаётся 0. В `Main control` потолки включаются только парой (если не греет хотя бы один, гасятся оба), поэтому **потолок не работает вообще**.
- **Лежаки парной** (`usersetpoints10`): заполняется только `[12]`, лежаки 2 и 3 (`[13]`, `[14]`) остаются с уставкой 0.

### 3.4. Режим «СПА» в СПА-зоне: потолок не греется
В `Main control` строки 188–189 дважды присваивают `setpoints[10] = 58`, а `setpoints[11]` остаётся 0. Из-за парного правила потолок потельни выключен. Судя по остальным режимам, во второй строке должно быть `[11]`.

### 3.5. Длительность пролива из интерфейса фактически не работает
- В `function 2` написано `global.get('userpoints24')` с опечаткой (нужно `usersetpoints24`). Получается `delay = undefined`, и trigger «Пролив обливного» использует свои 15 с по умолчанию.
- В расписании `delay = usersetpoints24` передаётся в trigger как `msg.delay`. Узел trigger трактует `msg.delay` в **миллисекундах**, а интерфейс подписывает поле «c» (секунды).
- `Shedule waterfall` запускается inject-ом каждые 5 с. Вне минуты срабатывания он каждый раз шлёт `Input 6 = "0"` через trigger «Обливное» в `Buttons`. Значит, `buttons[15]` сбрасывается в 0 не позже чем через 5 с. И ручной пролив кнопкой, и пролив по расписанию длятся **до 5 с**, а не заданное время и не 15 с.
- Switch `cont "waterfall"` пропускает в `function 2` и `waterfallsettings`. Ничего не ломается, но trigger пролива при этом зря запускается.

### 3.6. Расписание пролива: часы 00–04 не срабатывают
`currentHour = getHours() + 5` (сдвиг часового пояса без перехода через полночь) даёт значения 5…28. Время 00:00–04:59, заданное в интерфейсе, никогда не совпадёт.

### 3.7. Вентиляция: «Паровой душ» и «Естественная тяга» сбрасываются в «Пропарку»
В `Buttons` проверка `Time - ventilatetime > 900` выполняется при каждом вызове. При этом `ventilatetime` обновляется только нажатием «Проветривание». Через 15 минут после старта или после последнего «Проветривания» любое нажатие X1/X2 тут же откатывается в X0. Интерфейс при этом подсвечивает «Пропарку». Кроме того, сброс стоит **после** дублирования `buttons[4..7] = buttons[0..3]`, и реле парной на один цикл получают нажатый режим, а реле потельни — нет. Таймер, судя по всему, должен проверяться только при активном X3.

### 3.8. Вентиляция: в паровом душе 4 скорости, а не 3
Интерфейс подписывает кнопку «Паровой душ (3 ск.)». Сервер переключает ступени 1→2→3→4→выкл (`buttons[1] > 4`), а `vent[]` имеет 4 варианта. Текущую ступень интерфейс не показывает: иконка просто «вкл/выкл».

### 3.9. Мастер-клавиша не отражается в интерфейсе
Когда активна `buttons[12]`, сервер принудительно гасит бра и RGB. Интерфейс рисует рамки лампы и RGB по `buttons[8..11]`, поэтому показывает свет включённым. Команда `RGBlight` (payload 3) при этом меняет цвет, хотя свет погашен.

### 3.10. «Danger» не сбрасывается повторным нажатием
`Settings` и `waterfallsettings` на сервере переключаются туда и обратно, а `Danger` только устанавливается. Сбрасывается он лишь выбором любого режима. Пока он активен, `data.TP == "Danger"` при каждом обновлении возвращает экран журнала аварий.

### 3.11. Запарник: интерфейс показывает не тот датчик, по которому работает реле
Интерфейс выводит температуру запарника из `tempsensors[21]` (`wb-mai6_39` IN 4). Реле `EXT2_K2` управляется по `heaters[20]`, то есть по `tempsensors[20]` («тестовый блок», IN 3) и `setpoints[20]`. Это то же смещение индексов, что описано в `IO_list.md`.

### 3.12. Мелочи
- Ветки `case "Settings" / "waterfallsettings" / "Danger"` в обработке `TP_SPA` и `TP_SR` в интерфейсе мёртвые: сервер пишет эти значения только в `TP`.
- Чекбоксы расписания интерфейс обновляет через `.attr('checked')`. После того как пользователь кликнул по чекбоксу, это не меняет его отображаемое состояние (нужно `.prop`).
- Уставки парогенератора `[22]`, `[23]` не ограничены 100° (ограничение действует только для `i < length - 3`). Защиту обеспечивает только отсечка 420 °C в `Main control`.
- В режимах «Вечерний пляж» и «Хамам» уставка верхних зон равна текущей температуре. Из-за гистерезиса ±1 °C нагреватель просто сохраняет то состояние, в котором был на момент выбора режима.
- Физический вход `wb-mr6c_223/Input 6`, пришедший по MQTT, в `Buttons` не попадает: switch `eq Input 6` ни с чем не соединён. Обливным управляют только интерфейс и расписание.

## 4. Что совпадает
- Топики и значения `payload` (0 — СПА-зона, 1 — Парная) у всех кнопок режимов совпадают с обработчиками `Main control`.
- Таблица уставок пресетов, отображение уставок, датчиков и средних значений (лежаки, потолок) соответствуют индексам сервера.
- Цвета рамки RGB (белый, R, G, B, жёлтый, голубой, пурпурный) совпадают с функцией `RGB()` в `Buttons`. Рамка лампы (solid / dashed / dotted) совпадает с циклом бра `sconce`.
- Иконка аварии (`"Err"` в `tempsensors`) и журнал (`errormsg` / `timecatch`) соответствуют функции `Sensors`.
