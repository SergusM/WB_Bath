# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Контроллер бани на Wiren Board. Python-логика в `bath/` заменяет старый поток Node-RED (`flows.json`). Связь с WB идёт через MQTT с помощью библиотеки `python2wb`. Код, комментарии, документация и сообщения коммитов пишутся на русском.

## Команды

```bash
python -m pytest                                   # все тесты (брокер не нужен)
python -m pytest tests/test_heating.py::test_hysteresis   # один тест
python -m bath.io_config                           # самопроверка конфигурации: дубли топиков, таблица уставок
python3 -m bath.main --host <адрес WB> -v          # запуск против живого брокера
python tools/gen_web_demo.py                       # демо-данные для web/?demo
```

Сборки и линтера нет. `pytest.ini` задаёт `pythonpath = .`, поэтому пакет `bath` импортируется из корня. Сервис тоже запускается из корня (`WorkingDirectory` в `deploy/wb-bath.service`). Внутри пакета конфигурация импортируется относительно (`from . import io_config as cfg`), в тестах — `from bath import io_config as cfg`.

На контроллере стоит Python 3.9 (Debian 11). Синтаксис `X | Y` и `match` использовать нельзя. В модулях стоит `from __future__ import annotations`. python2wb требует `paho-mqtt<2`.

## Источники истины

- `bath/io_config.py` — всё железо (реле, входы, датчики, зоны нагрева), уставки пресетов и все константы времени и пределов. Логики в нём нет. Новые параметры добавляются сюда, а не в остальные модули `bath/`.
- `IO_list.md` и `UI_vs_flows.md` — разбор старого потока и старого `html/index.html`, включая список ошибок. Эти ошибки в новой логике намеренно исправлены. Не возвращайте старое поведение «для совместимости».
- `html/` — старый интерфейс. Новый код его не обслуживает, но его картинки, уменьшенные, лежат в `web/img/`.

## Архитектура

**Потоки.** `WbGateway` вызывает `loop_start()` из python2wb, и колбэки paho приходят в его поток. Колбэки только кладут `Event(kind, key, value)` в `gw.events`. Логика целиком однопоточная: `BathController.step()` берёт событие, раз в секунду вызывает `tick()`, затем `gw.flush()` и `publisher.maybe_publish()`. Не трогайте состояние из колбэков MQTT и не добавляйте блокировки.

**Время передаётся явно.** Методы подсистем принимают `now` (monotonic). Расписание обливного использует `wallclock()`. Контроллер получает `clock` и `wallclock` в конструкторе, на этом построены тесты.

**Применение состояния.** Подсистемы (`heating`, `ventilation`, `lighting`, `extras`) хранят только своё состояние. В `apply()` (у нагрева это `update(now)`) они выставляют все свои реле через `gw.set_relay()`. `BathController.apply()` вызывается после каждой команды, нажатия кнопки и тика. `set_relay` кэширует цель и пишет в MQTT только при изменении, поэтому вызывать его каждый раз дёшево. Реле напрямую через `wb.set` не пишутся.

**Очередь нагревателей** (`BaseGateway`). Включение реле из `ALL_ZONES` не пишется сразу, а встаёт в очередь. `flush()` отправляет не больше одного включения раз в `HEATER_ON_DELAY_S` (0.1 с), чтобы не перегружать контакторы. Выключение пишется сразу и снимает отложенное включение. `resync()` раз в `RELAY_RESYNC_S` сравнивает цель с обратной связью (`relay.topic`) и повторяет команду.

**Защиты нагрева** (`HeatingController.update`) важнее уставок:
- если датчик в ошибке или устарел (`SENSOR_STALE_S`), зона выключается;
- при перегреве выше `max_temp` зона выключается;
- потолки СПА (`SPA_CEILING_PAIR`) работают только парой;
- испаритель и парогенератор (`STEAM_GEN_GROUP`) выключаются вместе.

Аварии ставятся через `AlarmLog.set(key, active, msg)` и снимаются сами, когда условие проходит.

**Кнопки и интерфейс вызывают одни методы.** Физические входы через `ButtonTracker` (`inputs.py`; короткое и длинное нажатие, первое retained-значение игнорируется) и команды `/app/cmd` (`CommandApi.handlers` в `api.py`) вызывают одни и те же методы подсистем. Новая функция добавляется методом подсистемы, а затем подключается и к кнопке в `BathController._make_buttons()`, и к команде в `CommandApi.handlers`.

**Что сохраняется.** `config/settings.json` (`storage.py`, файл в `.gitignore`, пример — `config/settings.example.json`) хранит только ручные уставки и настройки обливного. Выбранные режимы нагрева, вентиляции и света не сохраняются: после старта всё выключено, вентиляция в «Пропарке». Это требование, а не упущение.

## MQTT API

Префикс задаёт `APP_PREFIX` (`/app`):
- `cmd` → ответ в `ack`;
- `state` (retained) — полное состояние, собирается в `build_state()`;
- `info` (retained) — справочник, собирается в `build_info()`;
- `event` — события;
- `online`.

Виртуальные устройства WB намеренно не создаются. Команды и аргументы описаны в `README.md`. При изменении состава команд обновляйте README и `ALL_COMMANDS_OK` в `tests/test_api.py`: тест проверяет, что покрыты все `handlers`.

## Веб-интерфейс (`web/`)

- Статические файлы без сборки и фреймворка. Скрипты подключаются обычными `<script>` в `index.html`, без ES-модулей. Синтаксис не новее ES2017: интерфейс работает на старых настенных планшетах.
- Браузер сам подключается к mosquitto WB по MQTT over WebSocket через `vendor/mqtt.min.js` (mqtt.js 4.3.8, локальная копия, интернета на объекте нет). Своего бэкенда у интерфейса нет, только MQTT API.
- `store.js`: последние `state`/`info`, статус связи, `send(cmd, args)` → Promise, который ждёт `/app/ack` с тем же `id`. Разделы в `js/views/*.js` строят DOM один раз и потом обновляют его на месте (`update(state, info)`). Так обновления состояния не сбивают ввод: степперы, ползунок, черновик расписания.
- Новая команда в `CommandApi.handlers` добавляется и в интерфейс, и в упрощённую модель `js/demo.js`.
- Демо: `index.html?demo` берёт `web/demo/*.json` из `tools/gen_web_demo.py`. Перегенерируйте их после изменения `build_state()` или `build_info()`. Для просмотра есть конфигурация `web` в `.claude/launch.json`.
- Оформление повторяет старую панель: тёмная тема, бирюзовый акцент `#0eb8c0`, объёмные иконки из `web/img/icons/`. За карточкой комнаты на экране нагрева — фото режима `web/img/modes/<ключ пресета>.jpg` (плюс `manual.jpg` и `off.jpg`). У нового пресета должно быть фото с таким же именем.
- После правок в `web/` увеличивайте `?v=N` у CSS и JS в `index.html`, иначе браузер берёт старые файлы из кэша.

## Тесты

`FakeGateway` пишет команды в `gw.writes` и сразу даёт обратную связь. Фикстура `rig` (`tests/conftest.py`) поднимает контроллер с управляемыми часами. Основные хелперы:
- `rig.temps()` и `rig.temp(zone, t)` задают показания с учётом поправки датчика;
- `rig.press(button, hold)` — нажатие кнопки;
- `rig.cmd(**json)` — команда в формате `/app/cmd`, возвращает ack;
- `rig.advance(dt)` — сдвиг времени и тик;
- `rig.flush_all()` — прогон очереди включения;
- `rig.on(relay)` — целевое состояние реле.

После команды включения нагревателей вызывайте `flush_all()`, иначе реле останутся в очереди.
